# Image 2.6 网页 GIF 实施计划

基准：v0.16.5（`249b471`）。承接已完成的 [上游及 GIF 调研](research/image26-free-web-gif-2026-11-12.zh-CN.md)，范围为免费网页登录账号的实验动画生成。

## 第一阶段：请求、验收和原始文件

- 在现有 2.6 网页通道接受 `output_format=gif`，通过提示词请求真实循环动画。
- 可选帧数和帧间隔只作为提示；不向网页协议注入未经验证的原生字段。
- 成功必须是至少两帧、所有帧可解码的 GIF；静态、单帧和损坏结果一次失败，不重新生成。
- 原始字节贯穿 base64、本地和 WebDAV 保存，正确使用 `.gif`、`image/gif`，记录实际动画元信息。

验收边界：`/v1/images/generations`、`/v1/images/edits`、图片存储的公开读取和下载接口。

## 第二阶段：所有入口、任务与界面

- Chat、Responses 的顶层和图片工具参数共用规范化规则，PNG 客户端默认值继续兼容。
- 任务提交、公开状态、保存、重新加载和续轮询保留 GIF 目标及提示参数。
- 续轮询只读取原账号、原会话，跨重启后仍按 GIF 目标验收。
- 图片页提供“GIF（实验）”，历史复用和重试保留选项，预览与下载使用原动画。
- 现有静态参考图可用于动画化；动画输入的完整编辑尚未验收，入口明确拒绝。

验收边界：Chat/Responses HTTP 接口、`/api/image-tasks` 的创建及恢复接口、前端格式识别及请求/历史选项。

## 第三阶段：回归与免费账号真实验收

- 按上述公开边界逐步增加失败回归并实施，通过隔离离线测试、前端类型检查和生产构建。
- 在服务器隔离目录运行本次源码，复用容器已有 Free 网页账号，记录脱敏结果。
- 分别验证 Sunburst、Flare 文生 GIF 和静态参考图动画化，完整解码并核对实际运动、帧数、时长、哈希和媒体类型。
- 真实上游若没有返回动画，报告失败证据并修正能力说明；离线合成 GIF 不计为真实生成成功。

## 第四阶段：审查、推送和发版

- 完成规范与需求审查，更新接入说明、真实验收记录和发布说明。
- 通过全部必要检查后提交、推送、创建发布标签和 GitHub Release，等待多架构容器镜像发布完成。
